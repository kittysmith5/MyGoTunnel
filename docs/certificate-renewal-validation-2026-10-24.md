# 公有 CA 证书与自动续期部署验证

2026-10-24，在 `feat/alpha-utls-connection-code` 分支完成。两端二进制保持原版本；本轮改变服务端证书配置、主客户端的地址/SNI/信任模式，并增加独立证书部署工具与定时任务。生产域名、配置、私钥和回滚快照不写入仓库。

## 迁移结果

- 复用已存在的 Let's Encrypt 域名与通配符证书，系统 CA 链和域名校验通过，有效至 2026-12-14；没有重新签发或替换现有 ACME 账户。
- 服务端继续监听8443并保留 HTTPS 入口、认证和其他参数。完整链与私钥形成不可变快照目录，配置原子更新两条路径；受控重启后检查实际运行文件、配置与新 TLS 证书。
- 主客户端仍监听51080，地址和 SNI 使用已直连源站的域名，移除旧叶证书指纹，启用系统 CA＋主机名验证；SOCKS 认证、UDP 策略及其他字段保持一致。61080的另一节点进程未变化。
- 浏览器等价的系统 CA＋主机名验证访问公网8443，HTTP 200，默认首页正常；不需要信任例外。

迁移前先用独立端口运行同版本服务端，内网客户端通过 CA 模式的 `-check-config/-health`，再确认公网域名路径可达。正式切换时客户端观察新域名证书出现后更新配置并重启，配置与二进制备份保留用于回滚。

## 定时更新

现有 ACME root cron 每天检查续期；已有域名配置使用 DNS API 验证，计划续期时间为2026-11-14。保留原证书、CA、私钥与完整链导出路径，只加入成功安装后的证书部署 hook。没有改动现有网站的 nginx 配置或443入口。

额外配置 `mygotunnel-cert-sync.timer`，每15分钟检查一次证书部署，作为 hook 失败或漏执行时的兜底。手动执行对应 oneshot，结果 success；timer已启用，cron服务正常。ACME install hook实际调用部署工具返回 unchanged，多次重复同步的服务端 PID不变。

源证书变化时，部署工具会校验公私钥匹配、公有 CA链、域名和有效期，再受控重启加载；没有变化则只核对实际运行证书。属于受控重启，并非热加载，已有连接遵循原grace退出策略。

**证书尚未到计划续期时间，本次没有强制重签，也没有实测未来 DNS API 续签请求。**已验证的是现有证书、定时任务、成功安装 hook，以及变化/不变两种部署路径；需要后续观察实际续期结果。
